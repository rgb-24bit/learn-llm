# 阶段5：解码采样与温度（推理侧的"随机变速器"）

**日期**: 2026-08-31
**主题**: 相同输入为什么得到不同输出 → 采样机制 → temperature/top_k/top_p → DeepSeek 特例

## 核心问题：模型输出的是"概率"，抽签决定下一个词

模型前向计算完最后一层（softmax）后，给出的是**概率分布**，不是**选定的词**：

| 下一个词 | 概率 |
|---------|------|
| 好 | 0.35 |
| 晴 | 0.25 |
| 不错 | 0.15 |
| 很棒 | 0.10 |
| 其他所有词 | 0.15 |

类比：模型是**偏心彩票机**（35% 的票是"好"、25% 是"晴"……）；选择由**掷骰子（多项式采样）**完成。同一输入两次生成 = 摇两次同一个偏心骰子 → 结果不同。

- 即使模型完全确定（概率 0.99），采样也可能以小概率抽到别的 → 不同输出
- "相同输入不同输出"不是 bug，是设计：语言中下一个词的"正确答案"往往不止一个

## 三个旋钮

| 旋钮 | 机制 | 类比 | 默认 |
|------|------|------|------|
| temperature | 先除以 T 再算 softmax：T<1 分布更尖（更确定），T>1 分布更平（更随机） | 骰子偏心度 | 1.0 |
| top_k | 只保留 logits 最大的前 K 个词，其余概率置 0 | 只让前 50 名参与抽签 | 常见 50 |
| top_p（nucleus 采样） | 从概率最大词开始累加，满 p 就截断（尾巴砍掉） | 累计份额 85% 的"大户"在场 | 常见 0.85-0.95 |

**数值算例**（logits: 好=2.0 晴=1.5 不错=0.8 很棒=0.5）：
- T=0.5 → 好≈66%（几乎雷打不动）
- T=1.5 → 好≈39%，四处都有机会（更随机）

**顺序**：logits ÷ temperature → top_k 过滤 → top_p 累积截断 → softmax → 采样（do_sample）或 argmax（贪心，确定性）。代码依据 minimind `model_minimind.py` generate()。

## 确定性与随机性的取舍

- **贪心（greedy/do_sample=False/T=0）**：永远选概率最大 → 确定性，但容易走上最短最俗的路径（固定短语、翻来覆去）
- **采样**：保留多样性，"重新生成"按钮 = 重新摇签
- 纯贪心的退化现象叫 **degeneration repetition**（重复循环、空洞废话），这是抽签存在的主要原因之一

## DeepSeek 特例：思考模式下温度不生效（官方行为，非 bug）

官方文档（2026-08，V4 时代）原文：
> 思考模式不支持 `temperature`、`top_p`、`presence_penalty`、`frequency_penalty` 参数。请注意，为了兼容已有软件，设置参数不会报错，但也不会生效。

要点：
1. V4 系列（deepseek-v4-flash / deepseek-v4-pro / deepseek-v4-flash-vision-exp）**思考模式默认开启**（thinking enabled，effort 默认 high）→ 所以普通用户默认情况下调温度就是无效的
2. 思考模式下真正的"旋钮"是 **reasoning_effort**（low / high / max；medium/xhigh 映射为 high）——控制"想多久/想多深"，而不是采样随机性
3. 想用 temperature：需显式关闭思考模式 `{"thinking": {"type": "disabled"}}`（或 Anthropic 格式 effort: none），此时采样参数才生效
4. 历史沿革：R1（2025-01）开始就不支持，V3.1/V3.2 延续，V4 官方明确写进指南
5. 推论：DeepSeek 上"重新生成"的差异主要来源于**思维链本身的随机性**（思考 token 内部采样），最终答案在低 effort 时更稳定
6. 其他弃用项：frequency_penalty / presence_penalty 已 deprecated，传入无效

## 验证方式（可用 API 实测）

- 同 prompt 相同参数连调 N 次，统计输出 diff（temperature=1 vs 0 vs 1.5）
- 思考模式：改 temperature 看输出是否变化 → 应无变化（官方确认）
- 非思考模式（thinking disabled）：改 temperature 应能看到分布变化

## 一行总结

**相同输入得到不同输出，不是模型出错，而是"下一个词"被故意设计成按概率抽签——偏心程度由 temperature/top_k/top_p 控制；而 DeepSeek 思考模式把这些旋钮拔了线，换了"思考强度"旋钮（reasoning_effort）。**
