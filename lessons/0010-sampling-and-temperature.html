🎲 采样与温度

lesson 0010 阶段 5 — 推理侧 · 解码机制

上一课我们跟到"模型输出一个概率分布"就停了。这一课回答一个你一定会遇到的问题： 同样的输入，为什么每次回答都不一样？答案是：模型只负责发彩票，选词靠抽签。

一、模型只输出概率，选词靠掷骰子

模型算完"今天天气"后，对下一个词给出的不是答案，而是一排概率：

模型内部的"彩票机"
下一个词    概率
好        0.35  ← 35% 的票
晴        0.25  ← 25% 的票
不错      0.15
很棒      0.10
其他词    0.15

把模型想象成一台偏心彩票机：35% 的票写着"好"，25% 写着"晴"…… 模型从不直接挑词，它只宣布"我的机器长这个样子"。 真正决定下一个词的是掷骰子（按概率抽签）。

两次调用相同输入 = 摇两次同一枚偏心骰子。第一次摇出"好"，第二次摇出"晴"， 都完全正常——这不是 bug，而是设计：因为语言里"正确的下一个词"往往不止一个。

二、三个旋钮：温度 / top_k / top_p

旋钮做什么类比
temperature先除以 T 再算概率：T<1 尖峰更尖（更确定），T>1 更平（更随机）骰子偏心度
top_k只保留最大的前 K 个词，其余出局只让前 50 名抽签
top_p从概率最大的词开始累加，加到 p 就截断累计份额 85% 的"大户"在场
数值算例：同一句话，同一组原始分数

原始分数（logits）：好=2.0，晴=1.5，不错=0.8，很棒=0.5

温度 0.5（冷） → 好 ≈ 66%   几乎雷打不动
温度 1.5（热） → 好 ≈ 39%   四处都有机会

这就是"冷热"命名来源：温度低，分布被冻成尖峰；温度高，摊平了。

实际调用顺序：logits ÷ 温度 → top_k 过滤 → top_p 截断 → 归一化成概率 → 掷骰子（采样）。
如果全撤掉（贪心模式 / temperature=0 / 不采样），输出就完全确定了——但容易走上最短最俗的路径，翻来覆去几句套话。保留一点随机，正是聊天产品愿意做的取舍。

三、DeepSeek 特例：温度真的不生效？

你观察得完全正确。DeepSeek 官方文档（2026 年 8 月版）白纸黑字写着： 「思考模式不支持 temperature、top_p、presence_penalty、frequency_penalty 参数。 为了兼容已有软件，设置参数不会报错，但也不会生效。」

背后的设计是：

模式采样旋钮真正的控制手段
思考模式（V4 默认开启）温度 / top_p 全部被拔线reasoning_effort：low / high / max（控制"想多深"）
非思考模式温度 / top_p 正常生效普通采样配置

为什么这么设计？思考模式下模型先输出一大段思维链再回答。让用户调温度， 会同时干扰"思考"与"回答"两段生成；而用户想要"更确定"时，真正有用的旋钮往往是 "多想一想"而不是"采样更保守"。于是 DeepSeek 干脆把采样参数在思考模式下禁用， 换上了思考强度旋钮。

推论：在 DeepSeek 上点"重新生成"时，答案差异主要来自思维链本身的随机性， 而不是温度。想验证：同参数连调几次，对比思考内容与最终答案。

⚠ 其他已弃用参数：frequency_penalty、presence_penalty 在 DeepSeek API 中已标记 deprecated，传入也不会产生任何效果。

四、一行总结

答案

相同输入得到不同输出，不是模型出错，而是"下一个词"被故意设计成按概率抽签—— 偏心程度由 temperature / top_k / top_p 控制；而 DeepSeek 思考模式把这些旋钮拔了线， 换了"思考强度"旋钮（reasoning_effort）。
